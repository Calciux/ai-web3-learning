## 学到的重点

### AI 赛道 vs Web3 赛道的核心交集

AI 和 Web3 本质上是互补的：AI 解决「智能决策」问题，Web3 解决「可信协作」问题。两者结合时，核心矛盾在于 AI 的链下计算与链上验证之间的信任鸿沟。

---

### Decentralized AI Infrastructure：链下计算 + 链上激励

这个方向解决的是：**如何让一群互不信任的人贡献算力、数据或模型，并公平地获得回报。**

**核心模式**：链下计算 / 链上激励、结算、验证、服务发现

**关键组件拆解：**

| 层面 | 做什么 | 链上/链下 |
|------|--------|----------|
| 计算 | 训练/推理任务实际执行 | 链下 |
| 结算 | 完成任务后自动打款 | 链上（智能合约） |
| 验证 | 证明计算结果是正确的 | 混合（zk-SNARK / 挑战期） |
| 服务发现 | 在哪找计算资源 / 谁提供服务 | 链上 |

**代表性项目：**

- **Bittensor (TAO)** — 创建一个去中心化的神经网络市场。子网（Subnet）各自负责不同的推理任务，矿工提供模型输出，验证者打分，链上根据分数分配 TAO 奖励。本质上是 **用代币激励模型的涌现**。
- **Gensyn** — 专注于深度学习训练的计算验证。通过概率性验证（随机抽查）来证明计算确实被正确执行，无需重跑整个训练。
- **Akash Network** — 去中心化的云计算市场，GPU 资源按需租赁。用 Cosmos SDK 构建，竞价模式匹配供需。

**AI 背景可以这样理解**：就像 Hugging Face + AWS 的合体，但所有调度、定价、信誉信息都跑在链上公开可查。

---

### AI Agent + Wallet：自主执行链上操作

AI Agent 要真正有用，不能只停留在「分析数据」的阶段，必须能**主动执行链上操作**——转账、质押、兑换、投票等等。这就需要一个 Agent 可控的钱包。

**Agent 钱包的核心问题：**

1. **谁控制私钥？** — Agent 运行时需要签名能力，但私钥暴露给 Agent 意味着巨大的安全风险
2. **授权范围怎么限制？** — Agent 应该只能花 N 个 ETH，只和特定合约交互
3. **人类怎么审核 Agent 的链上动作？** — 签名之前需要交易模拟和风险提示

**当前主流方案：**

- **Coinbase AgentKit** — 给 AI Agent 封装了一组链上操作工具（transfer, swap, deploy NFT 等），底层使用 CDP API，Agent 通过函数调用来发起交易，签名由 CDP 托管钱包完成。Agent 不需要接触私钥。
- **LangChain + Wallet 集成** — 通过 Tool 协议将 wallet 读写包装成 Agent 可调用的函数
- **ERC-4337（账户抽象）** — 让钱包变成智能合约，支持自定义签名验证逻辑、Gas 代付、会话密钥。Agent 可以持有一个有限的会话密钥，在约束范围内自主操作。

**适用场景**：Agent 自动 DCA、自动收割收益、跨链桥接、链上治理投票——这些动作如果都要人类手签，Agent 就失去了意义。

---

### 智能钱包和安全助手：签名前的最后一道防线

这是目前最落地的方向。核心逻辑：**用户签名之前，系统自动模拟交易结果，识别风险。**

**为什么需要这个？**
- 绝大多数链上攻击发生在用户签名的那一瞬间（授权钓鱼、Permit 签名窃取、盲签）
- 用户往往看不懂合约调用的底层含义，特别是 Permit / approve 这类授权签名

**安全助手做的事：**

1. **交易模拟（Simulation）** — 在签名前，在本地或沙箱环境预执行交易，返回预期结果：你会失去什么、得到什么、授权多少额度
2. **风险评分** — 检测目标合约是否被标记为恶意、是否是新部署的（蜜罐检测）、授权额度是否过高、是否有 Approve 钓鱼特征
3. **自然语言解释** — 将底层交易数据翻译成人话：「这个合约将请求你授权无限额度的 USDC，且合约部署仅 2 天前」

**代表性产品：**

| 产品 | 定位 |
|------|------|
| **Rabby Wallet** | 模拟交易 + 风险提示，支持多链，Gas 自动估算 |
| **Fire (wallet.equation.com)** | AI 驱动的交易解释，专注于以太坊 |
| **Blockaid** | 安全基础设施，被 MetaMask 和 Coinbase 集成 |
| **GoPlus Security** | 开放的合约安全评分 API，任何钱包都能接入 |

**技术栈**：交易模拟通常用 Tenderly Simulation API 或自建 Fork 节点（Anvil 分叉主网状态后 dry-run）。

### AI 链上分析工具：从数据噪声中提取信号

链上数据是公开的、完整的、不可篡改的——但也是灾难般混乱的。AI 在这里的价值是**降噪和发现模式**。

**链上分析要解决的问题：**

1. **实体聚类（Address Clustering）** — 一个用户有几十上百个地址，AI 通过交易模式（资金流入流出时间、Gas 习惯、交互合约集合）把它们聚合成一个实体
2. **异常检测** — 检测大额异动、闪电贷攻击前兆、MEV 机器人抢跑模式
3. **标签化（Labeling）** — 给地址打标签（CEX / 做市商 / 钓鱼 / MEV 机器人 / 合约部署者）

**关键工具：**

| 工具 | 核心能力 |
|------|---------|
| **Dune Analytics** | 用 SQL 查询链上数据，可视化仪表盘，社区共享 |
| **Nansen** | AI 驱动的钱包标签和资金流向追踪，「Smart Money」跟踪 |
| **Arkham Intelligence** | 可视化实体的链上图谱，类似链上的 LinkedIn |
| **The Graph** | 去中心化索引协议，子图（Subgraph）将链上事件组织成可查询的 API |

**对 AI 背景同学**：可以把链上分析看作一个超大规模的时序图分析问题——实体是节点，交易是有向边，AI 模型做链路预测和异常检测。Nansen 的「Smart Money」本质上就是用 ML 给地址的「聪明程度」打分，然后追踪他们的下一步动作。

### 交易所和 DeFi 智能风控系统

这部分是 AI + Web3 在**金融安全**最具商业价值的应用。

**交易所风控场景：**

1. **提币地址风险评估** — 用户申请提币时，AI 检查目标地址是否涉及洗钱、混币器、钓鱼地址。Whale Alert + Chainalysis 的对地评级系统
2. **交易模式异常检测** — 检测刷量交易、清洗交易（Wash Trading）、市场操纵模式（Pump & Dump 识别）
3. **KYC/AML 中的 AI** — 身份验证、活体检测、跨平台身份关联

**DeFi 风控场景：**

1. **协议安全监控（Gauntlet）** — 模拟极端市场条件下（ETH 跌 50%、流动性撤走 80%）的清算风险，动态调整风险参数
2. **闪电贷攻击检测** — 在 Mempool 层面识别攻击交易模式，提前标记
3. **价格预言机安全** — 监测预言机喂价与市场价格的偏离程度，防止价格操纵攻击（TWAP vs 瞬时价格）
4. **流动性深度监控** — 检测矿池异常撤出、Sandwich 攻击、MEV 机器人前置交易模式

**AI 的独特价值**：传统规则引擎（if 余额 > X then 告警）误报率高、响应慢。AI 模型可以学习正常行为基线，在链上交易的毫秒级窗口内做出判断。

**代表性项目**：

| 项目 | 领域 |
|------|------|
| **Gauntlet** | DeFi 风险模拟 + 参数优化 |
| **Chaos Labs** | DeFi 实时风险监控（Aave 等协议接入） |
| **Chainalysis / Elliptic** | 链上 AML 分析，服务于交易所和监管机构 |
| **TRM Labs** | AI 驱动的链上反欺诈，实时评分 API |
